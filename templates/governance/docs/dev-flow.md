# 开发流程（8 步，每步都有退出条件）

顺序不许跳。每步的「退出条件」就是闸门要验的东西（见 `.dsh/gates.yml`）。

| # | 步骤 | 谁做 | 退出条件（必要条件） |
| --- | --- | --- | --- |
| 1 | 头脑风暴 | 主 agent | 意图/边界/不做的事写下来 |
| 2 | 写计划 | 主 agent | `plans/NNNN-*/task_plan.md` 存在，含验收标准 |
| 3 | TDD 红 | 主 agent | **测试先跑出过一次失败**（退出码≠0，且早于源码改动） |
| 4 | 实现绿 | `developer` | 目标测试通过；只动计划里列的文件 |
| 5 | 独立评审 | `reviewer` | 报告给 **PASS**（FAIL 列出阻断项） |
| 6 | 完成前验证 | 主 agent | 验证命令真实跑过、退出码 0，贴出输出 |
| 7 | 交付验收 | `deploy-ops` | 验收证据（L1 界面 + L3 库行）存在，否则不算交付 |
| 8 | 合并 | 主 agent | 无未评审的越界文件；台账同轮更新 |

## 三条最容易糊弄的地方（闸门就冲这三处）

1. **假 TDD**：先写实现再补测试。证据：测试必须先红，且红的记录早于实现改动。
2. **假完成**：只有接口返回（L2）就宣布修好。证据：L1 界面 + L3 库行同时成立。
3. **早退**：子代理只说「让我看看 X」就结束，结论一个字没给。证据：报告文件非空。

## 排查 bug

先建确定性可复现的反馈命令，再提可证伪假设；不许「先猜一个再改」。
