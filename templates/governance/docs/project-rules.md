# 项目规则（可执行，跟着项目走）

重复出现的事，升级成规则。**规则要能被机器查，才叫规则。**

## 四档升级

| 档 | 形态 | 成本 |
| --- | --- | --- |
| 1 | 一句提示（AGENTS.md） | 几分钟 |
| 2 | 可 grep 的清单 / 词表 | 半小时 |
| 3 | 脚本（跑一下就知道对错） | 半天 |
| 4 | 闸门（不通过不许动） | 一两天 |

**不许一步跳到第 4 档。** 升闸门要三条同时成立：重复出现 + 后果大 + 判据机械。
判据需要判断力的（代码写得好不好）停在第 3 档，硬塞成闸门只会天天误报。

## 默认四条

| 编号 | 规则 | 判据 | 档 |
| --- | --- | --- | --- |
| R1 | 说完成要带证据 | 出现「已上线/已修复」但整份文件无证据词 | 3 |
| R2 | 改测试未改源码 | `x.test.ts` 变了、`x.ts` 没变 | 3 |
| R3 | 空话要带数字 | 新增行有「优化/提升/大幅」但没有数字 | 3 |
| R4 | 禁用词 | 词表命中 | 2 |

禁用词：`赋能` `抓手` `降本增效` `底层逻辑` `范式转移`

## 验收

连续两周没红过的规则删掉；天天红的才升闸门。
**拦得住的才叫闸门，拦不住的是标语。**
