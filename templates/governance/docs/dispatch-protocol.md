# 派发协议（brief + 报告契约 + 验收循环）

## brief 必含七段

```
## 任务       一句话，动词开头
## 背景       为什么做、用户已拍板的决定
## 涉及文件   精确到包/目录，越界即失败
## 约束       不许动什么、必须遵守哪条红线
## 验收       跑什么命令算过
## 不要做     计划里明确不做的内容
## 报告       按该角色的交付格式
```

## 单次模式必加一条

> **禁止中途汇报进度**。你运行在单次模式：输出任何不含工具调用的文本都会立即结束本次运行。
> 进度只写报告文件（开工先建骨架，边做边追加），只在「全部完成」或「遇到阻断」时输出一次结论。

## 报告契约

- 每个角色有自己的固定交付格式（见 `agents/*.md`），**缺字段即视为没完成**。
- 评审类必须给 **PASS/FAIL**，不许「总体不错」。
- 运行结束但报告文件为空/不存在 → 判**早退**，整轮重派。

## 验收循环

1. 主 agent 写 brief → 派发 → 拿报告
2. 报告缺字段 / 给不出证据 → 原样重派一次（补 brief，不补理由）
3. 连续两次同一处失败 → 停，改判据或改测试，不要第三次盲试

## 拆段原则

需要等外部周期的验证（部署就绪、小时级调度、批处理跑完）**必须单独成段**，
带复检命令、期望值、失败门槛；不要塞进部署段一起等。
