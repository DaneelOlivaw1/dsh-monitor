# 台账标准（跨项目统一）

**内容各项目不同，种类和格式必须一样。** 读台账的不只是人，还有脚本和 agent。

## 目录（固定）

```
memory/
├── MEMORY.md      # 索引，唯一入口，按名称字母序
├── TEMPLATE.md    # 条目骨架
├── constraints/   # 必保行为
├── pitfalls/      # 踩坑
└── reference/     # 参考 / 步骤 / 项目约定
```

## 五种类型（判据固定）

| type | 一句话 | 该问自己的问题 | 放哪 |
| --- | --- | --- | --- |
| `必保行为` | 改了会悄悄回归的硬约束 | 违反会不会出线上事、或安静地算错？ | `constraints/` |
| `gotcha` | 反直觉、容易误判的坑 | 这个坑是不是已经犯过第二次？ | `pitfalls/` |
| `runbook` | 一串固定步骤 | 下次还得照着再做一遍？ | `reference/` |
| `reference` | 常查的事实、ID、口径 | 查一次要用很多次？ | `reference/` |
| `project` | 本项目的约定与决策 | 这是「本项目的规矩」？ | `reference/` |

## 条目字段（机器可读）

```yaml
---
name: <project>-<主题>
description: 一行说明 +（何时必读）
type: 必保行为 | gotcha | runbook | reference | project
---
```

正文三段：`## 涉及文件` / `## 必保行为`（runbook 换成 `## 步骤`）/ `## 回归测试`。
**缺 type 或 description 的条目视为无效，脚本与 agent 一律跳过。**

## 索引行

```
- `[[<name>]]` —— <description>（<何时必读>）
```

## 写入规矩（防腐）

1. 极简追加：日期 + 涉及文件 + 必保行为；长背景放正文。
2. 同轮加索引：没索引 = 没记。
3. 同轮更新：改了被覆盖的代码就回头改条目。
4. 保留被推翻的痕迹：「原为 X，YYYY-MM-DD 改为 Y，原因…」。
5. 写不写看三条之一：线上实报 bug / 外部系统反直觉 / 跨两处必须同步的契约。
