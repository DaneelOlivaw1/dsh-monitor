# 项目治理模板（框架无关）

四层，各归其位。内容各项目自己填，**结构不要改**。

```
agents/*.md            角色：谁做什么、不做什么、交付什么
.agents/skills/        流程：TDD / 评审 / 派发 / 复盘（Agent Skills 标准）
.dsh/gates.yml         闸门：机器执行的退出条件（block / warn / 打回）
memory/                台账：事实沉淀，改代码前先查
```

## 为什么是四层

- **角色**管边界：一个 agent 只干一件事，写清「不做什么」比写清「做什么」更能防越界。
- **流程**管顺序：每一步有退出条件，不是建议。
- **闸门**管执行：条件必须**机械可判**——能数、能 grep、能跑脚本。判不了的不要做成闸门。
- **台账**管记忆：同一个坑踩第二次，就该写下来；第三次，就该变成闸门。

## 铺到新项目

```bash
bash <dsh-monitor>/scripts/init-governance.sh /path/to/project
```

已存在的文件不会被覆盖。

## 三条纪律（闸门只验必要条件）

1. **只验必要条件**：充分条件要判断力，会误杀；必要条件廉价、无争议，叠几条就够用。
2. **宁可漏放，不可乱杀**：误杀会逼出「应付闸门」的行为，比漏放更伤。
3. **同一句话写第二遍 → 升级**：提示 → grep 清单 → 脚本 → 闸门，不要一步跳到闸门。
