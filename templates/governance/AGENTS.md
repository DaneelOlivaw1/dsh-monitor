# 项目协作入口

始终用中文交互；回复、注释、提交信息都用中文。

**汇报铁律**：只说「结果和效果」（能不能用、跑通没跑通、下一步），不说技术过程。

## 四层结构

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 角色 | `agents/*.md` | 谁做什么 / 不做什么 / 交付什么（框架无关） |
| 流程 | `docs/dev-flow.md` + `.agents/skills/` | 8 步开发流程，每步有退出条件 |
| 闸门 | `.dsh/gates.yml` | 机器执行的退出条件；判不了的别放进来 |
| 台账 | `memory/MEMORY.md` | 一行一条 + wikilink，按 description 判断相关性 |

## 冷启动顺序

1. 读本文件
2. 读 `docs/dev-flow.md` 的「当前在哪一步」
3. 改代码前查 `memory/MEMORY.md` 相关条目
4. 需要派活时读 `docs/dispatch-protocol.md`

## 架构防腐（强制）

1. 本文件保持「薄」：只放指针，细节进 `docs/`
2. 新增台账条目 → 同轮在 `memory/MEMORY.md` 加索引行；格式照 `TEMPLATE.md`，格式不对先改格式再写内容
3. 新计划 → `plans/NNNN-YYYY-MM-DD-标题/`，并更新「当前状态」
4. 交付证据 → 计划同目录的 `evidence/`（`INDEX.md` 一行一条 + 截图 / 输出 / 退出码），只追加不覆盖
5. 新决策 → `docs/adr/` 或 findings，保证从索引能找到
6. 新角色 → `agents/`；新技能 → `.agents/skills/`；别塞根目录

## 禁止事项

- 生产库写入 / 迁移 / 权限变更，**执行前必须拿到用户明确确认**
- 不读 `.env`、密钥文件（除非用户授权）
- 钱用定点数（decimal），不用浮点
- 不在用户没要求时擅自 commit / push
- 不把临时排查文件、草稿、凭证提交进仓库
