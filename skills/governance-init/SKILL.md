# 铺治理骨架

**不是复制模板，是给这个项目配一套合身的。** 复制会造出两套并存的东西，比没有更糟。

模板只当参考：`<plugin>/templates/governance/`（角色 / 流程 / 闸门 / 台账的骨架）。

## 一、先读，别先写

按顺序看，缺哪样记下来，**不要边说边改**：

1. `AGENTS.md` / `CLAUDE.md` —— 已有入口？是否已经分层？（很多项目已经有，只是没闸门）
2. `agents/` 或 `.pi/agents/` 或 `.claude/agents/` —— 已有角色？边界写了吗？
3. `memory/` 或 `.memory/` —— 已有台账？索引在不在？
4. `docs/` —— 有没有 dispatch 协议、开发流程、ADR？
5. `.dsh/gates.yml` —— 有闸门吗？
6. 语言与命令：`Cargo.toml` / `package.json` / `pyproject.toml`；测试、构建、格式化的真实命令。

## 二、只补缺的那层

| 已有情况 | 动作 |
| --- | --- |
| 有 AGENTS.md 且已分层 | 不动，只在它的「记忆索引」加一行指向新文档 |
| 有 AGENTS.md 但一坨 | 只在末尾加「四层结构」表 + 冷启动顺序，**不重写** |
| 有 agents/ | 只补缺的角色；已有的按「不做什么」检查一遍，缺就补一段，不改职责 |
| 有 memory/ | 只在缺 `TEMPLATE.md` / 缺索引行时补 |
| 没有 `.dsh/gates.yml` | 新建，只放这个项目真用得上的闸门（3–5 条，宁少不多） |

**每个项目最多新增 4 个文件**（外加 `.dsh/gates.yml`）。超过就说明在硬塞。

## 三、按项目定制（关键）

不许原样搬模板里的命令与角色：

- **命令**：闸门和流程里写的测试/构建/格式命令，必须换成这个项目真实跑的（从 `package.json` / `Cargo.toml` / Makefile 里读出来）。
- **角色**：只保留这个项目真的会派的角色。纯前端项目可能没有 `deploy-ops`；数据项目可能没有 `developer`。
- **交付证据**：这个项目「什么算完成」写具体——网页是截图，API 是库行，CLI 是退出码。
- **红线**：从这个项目已有的规则里抄（不许 unsafe / 金额用定点数 / 生产库只读），别用模板的默认红线。

## 四、闸门只要必要条件的

每条闸门写三样：`when`（什么时候判）、`require`（判什么）、`enforce`（block / warn）。

判据必须能机械判：能不能数、能不能 grep、能不能跑脚本。
**判断不了的一律不要做成闸门**（比如「代码写得好不好」），写成流程里的一句话就行。

默认只放这几条（按项目取舍）：

1. 改代码前有计划文件
2. 测试先红（有一次失败记录早于源码改动）
3. 评审 PASS 才合并
4. 说完成要带证据（L1 界面 + L3 库行）
5. 子代理报告非空（防早退）

## 五、汇报格式（固定）

```
读完的现状：<已有 agents / memory / docs / 命令>
新增：<文件: 一句话为什么>
改动：<文件: 改了什么、为什么不重写>
闸门：<id: 判据 + block/warn>
没动：<哪些已存在所以跳过>
下一步：<这个项目应该先补哪一层>
```

## 边界

- **不覆盖**已有文件；要改先说明改哪几行。
- **不搬家**：已有的 `memory/`、`agents/` 原地不动，不许合并成新目录。
- **不写代码**：只铺骨架，不实现功能。
- 铺完不 commit（等用户看过）。
